Authoring kit for AI assistants

Build a playable board game from one prompt.

Two pieces, no SDK: a skill that teaches your assistant the workflow, and a hosted MCP server that creates, validates, simulates and publishes the game. Your assistant writes canvas.json, logic.lua, scenarios.json and INSTRUCTIONS.md — the platform runs them.

$ npx @pandya.ai/skill

Works with Claude Code · Claude Desktop · Codex · Cursor · VS Code · Gemini CLI · Antigravity · OpenCode · Windsurf · any MCP client — @pandya.ai/skill@0.1.0 on npm

01

Install the skill

The installer drops one markdown file into your assistant's skill directory. It never edits your MCP config — that is step 02. 

# interactive: pick your assistant(s)
npx @pandya.ai/skill

# or target explicitly
npx @pandya.ai/skill install --target claude,codex,cursor,gemini,opencode
npx @pandya.ai/skill install --target all --scope project
TargetInstalls to
claude~/.claude/skills/pandya-authoring/SKILL.md
cursor./.cursor/rules/pandya-authoring.mdc (project)
gemini~/.gemini/config/plugins/pandya/skills/pandya-authoring/
opencode~/.config/opencode/skills/pandya-authoring/

npx @pandya.ai/skill list shows every target and destination · npx @pandya.ai/skill mcp prints the config snippets below · --dry-run writes nothing.

02

Connect the MCP server

One endpoint, both transports: https://pandya.ai/mcp (streamable HTTP). SSE-only clients can use https://pandya.ai/mcp/sse. Pick your assistant:

Claude Code

Run in the project where you want the tools available.

claude mcp add --transport http pandya https://pandya.ai/mcp
claude mcp list        # pandya … connected

Project-scoped instead (written to .mcp.json, safe to commit):

{
  "mcpServers": {
    "pandya": { "type": "http", "url": "https://pandya.ai/mcp" }
  }
}

Codex CLI

~/.codex/config.toml (or the project's .codex/config.toml).

[mcp_servers.pandya]
url = "https://pandya.ai/mcp"

# Headless only — see Auth. Interactive runs use OAuth.
# bearer_token_env_var = "PANDYA_API_KEY"

Cursor

Settings → MCP → Add new MCP server (type remote). Or check in .cursor/mcp.json:

{
  "mcpServers": {
    "pandya": { "url": "https://pandya.ai/mcp" }
  }
}

VS Code (Copilot agent mode)

.vscode/mcp.json, then MCP: List Servers → start pandya.

{
  "servers": {
    "pandya": { "type": "http", "url": "https://pandya.ai/mcp" }
  }
}

Gemini CLI

~/.gemini/settings.json (or the project equivalent), then restart.

{
  "mcpServers": {
    "pandya": { "httpUrl": "https://pandya.ai/mcp" }
  }
}

Antigravity

MCP panel → add a remote server.

name: pandya
url:  https://pandya.ai/mcp

Prefer a git-clone plugin? Clone this repository into the plugin directory and the skill plus mcp.json are picked up on restart:

git clone https://github.com/Kuntabille/pandya.ai.git ~/.gemini/config/plugins/pandya

OpenCode

opencode.json — note the mcp.servers nesting: a server placed directly under mcp is ignored.

{
  "mcp": {
    "servers": {
      "pandya": { "type": "remote", "url": "https://pandya.ai/mcp" }
    }
  }
}

Claude Desktop

Settings → Connectors → Add custom connector. Name it pandya, paste https://pandya.ai/mcp, connect and sign in.

Builds that predate Connectors only load local (stdio) servers — use the stdio only tab.

Windsurf

MCP settings, or ~/.codeium/windsurf/mcp_config.json.

{
  "mcpServers": {
    "pandya": { "serverUrl": "https://pandya.ai/mcp" }
  }
}

Any client that only speaks stdio (Pi, Hermes, older builds)

The bridge proxies the remote server over stdio and performs the OAuth sign-in on first run.

npx -y mcp-remote https://pandya.ai/mcp

# non-interactive: skip the browser, pass a bearer token
npx -y mcp-remote https://pandya.ai/mcp \
  --header "Authorization: Bearer $PANDYA_API_KEY"

Point the client's command/args at that npx invocation; nothing else to install.

03

Prove it works

Ask the assistant to call get_authoring_guidelines. A working setup returns the Canvas and Logic prompts. If the server is reported unavailable, the client did not follow the OAuth challenge — check the URL and the client version. 

Use the pandya MCP server to call get_authoring_guidelines,
then create a two-player abstract game and validate it.

Authentication

Interactive clients need no setup. An unauthenticated request answers with a WWW-Authenticate challenge pointing at https://pandya.ai/.well-known/oauth-protected-resource/mcp; your assistant opens a browser, you sign in, and the client keeps the grant. Review or revoke grants at pandya.ai → Profile → Developer → Connected applications.

Non-interactive agents (CI, cron, a container) cannot complete that flow. Mint a pandya_mcp_… token with your session and send it as a bearer token: 

curl -s https://pandya.ai/user.UserService/GenerateMCPToken \
  -H "Authorization: Bearer $PANDYA_SESSION_JWT" \
  -H "Content-Type: application/json" \
  -H "Connect-Protocol-Version: 1" \
  -d '{"name":"ci-agent","expiresInDays":90}'

The raw token is returned once; only its hash is stored. Existing tokens keep working — new integrations should prefer OAuth.

What the server gives you

create_gameScaffold a draft: canvas, logic, scenarios, instructions.
get_authoring_guidelinesThe Canvas and Lua authoring prompts.
get_lua_librariesEvery engine hook, host API and preloaded library.
get_ui_componentsRenderer primitives and theme presets.
get_canvas_catalogEvery accepted canvas field, plus the play-frame contract.
validate_logic_and_canvasContract checks, simulation, and your rule scenarios.
simulate_game_logicHeadless random play to catch runtime errors.
simulate_gameplayEnd-to-end browser simulation of board and rules.
update_gameWrite the draft; a failing scenario rejects the write.
publish_gameValidate and ship the draft. Publishing forks a new draft.
get_gameFetch the draft (or source: "published").
upload_assetModerated image upload, referenced by asset id.
get_playtest_logsExecution logs for a live playtest session.

Troubleshooting

The client says the server is unavailable

Check the URL is exactly https://pandya.ai/mcp. Then confirm the endpoint answers with an auth challenge rather than a web page:

curl -i -X POST https://pandya.ai/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize"}'

A 401 with WWW-Authenticate: Bearer is correct and expected.

npx @pandya.ai/skill fails to resolve the package

Check the registry first: npm view @pandya.ai/skill version should print 0.1.0 or newer. A cached npx can also pin an old version — run it as npx --yes @pandya.ai/skill@latest. For Gemini/Antigravity, the git-clone plugin path in step 01 remains available.

The tools exist but game validation fails

Ask for get_authoring_guidelines and get_canvas_catalog first; they carry the current contract. Then re-run validate_logic_and_canvas — its findings are written to be actionable.
